git revert <commit>

### 2. 版本级

```bash
# 切回上一个稳定版本（只读检查）
git checkout v2.9.1-huawei.1   # 发布标签（若已创建）
# 或
git checkout v2.9

# 只在本机丢弃未提交修改（危险；不会影响远端）
git reset --hard <tag>
```

> **禁止** `git push --force` 覆盖共享历史。远端回滚应通过新的 revert 提交完成。

### 3. 发布产物

- 保留上一个发布包 `1401-Windows-2.9.0.zip` 及其 SHA-256；新包验证失败时回退到它。
- 回滚后重新运行 `scripts\build-release.cmd` 与 `reports/tests/windows-verification.json` 的验证。
- EFI 产物：`out/huawei-efi-release` 为本次验证版本；不要在没有记录的情况下替换用户 U 盘上的 EFI。

### 4. 数据/磁盘

- 本项目**未修改** aigo U350、ACASIS TBU405Pro、WD SN740。
- 真实写盘/格式化不可通过 Git 回滚；必须按 `bugs/03` 的授权边界操作，并自行承担数据风险。

## 二、上游同步（可重复）

### 1. 原则

- 先 fetch，不直接覆盖自有修改。
- 在独立集成分支 merge（`--no-ff`），不使用 rebase 改写已推送历史。
- 合并后必须跑全量测试 + Huawei EFI 构建 + `ocvalidate`；失败不得合入 `main`。
- 只推送自有 Fork；不向上游写 PR/Issue（`AGENTS.md` 要求）。
- 不强制推送。

### 2. 步骤

```bash
cd /d/code/Ai/1401

# 0) 记录当前状态
git status --short
git rev-parse HEAD
git rev-parse upstream/main

# 1) 获取官方更新与标签
git fetch upstream --tags --prune

# 2) 检查 Release / CHANGELOG / Issue
gh release list --repo nullmoth/1401 --limit 10
gh release view --repo nullmoth/1401 <new-tag>
git diff v2.9..upstream/main -- CHANGELOG.md docs/ | head -200

# 3) 建立集成分支（从 develop）
git checkout develop
git checkout -b integration/upstream-$(date +%Y%m%d)

# 4) 合并上游（保留历史；冲突时按文件解决）
git merge --no-ff upstream/main -m "Sync upstream $(git rev-parse --short upstream/main)"

# 5) 冲突处理
#    - 自有补丁集中在：p1401/usbwriter.py、rawdisk.py、apple.py、fullinstaller.py、
#      engine.py、validate.py、netsupport.py、utbmap.py、intel_gpu.py、huawei.py、
#      machine_recipes.json、windows/App/*.cs、tests/*、docs/*。
#    - 先看上游是否已修同一问题；若已修，优先采用上游实现并删除我们的重复补丁。
#    - 解决后 git add <files> && git merge --continue。

# 6) 回归
scripts\run-tests.cmd
.\.venv\Scripts\python.exe -m p1401 build out\huawei-scan\Report.json out\huawei-scan\ACPI `
  out\huawei-efi-sync --macos 25 --json
.\.venv\Scripts\python.exe scripts\verify_efi.py out\huawei-efi-sync

# 7) 记录同步报告
#    新建 upstream-notes/sync-YYYY-MM-DD.md：上游 SHA、Release、变更摘要、冲突、
#    测试结果、Huawei 构建结果、回滚点。

# 8) 通过后合并
git checkout develop
git merge --no-ff integration/upstream-YYYYMMDD
git checkout feature/huawei-1401
git merge --no-ff develop
# 稳定发布时：
git checkout main
git merge --no-ff develop
git tag -a vX.Y.Z-huawei.N -m "1401 X.Y.Z Huawei fork"
git push origin main develop feature/huawei-1401 --tags
```

### 3. 自动化脚本

`scripts/sync-upstream.sh` 执行步骤 0–4，并在合并后运行测试；失败时保留集成分支供人工处理。它**不会** push，也不会 force。

### 4. 同步报告模板

```markdown
# 上游同步 YYYY-MM-DD
- 上游 before/after SHA:
- 新 Release/Tag:
- CHANGELOG 摘要:
- 受影响文件/冲突:
- 上游是否已修我们的某个补丁:
- 测试结果（1190 项基线 + corpus）:
- Huawei EFI 构建/ocvalidate:
- 回滚点:
```

### 5. 已知同步风险

- OpenCore/kext 下载源是上游 latest；同步后 `ocvalidate` 版本会随缓存变化，需重新生成/验证 EFI。
- 上游 `machine_recipes.json`/`known_machines.json` 可能新增行；保留我们的 Huawei 行，按 id 去重。
- 上游若修改 `usbwriter.py`/`rawdisk.py` 的擦盘路径，必须重新审查身份复核是否仍在破坏性操作内部。
- 上游若修改 `apple.py`/`fullinstaller.py`，重新检查预检哈希、本地镜像擦盘前校验、#161 逻辑是否仍成立。
- 上游若修改 `Engine.Q`/`MainForm` 写盘参数，重新运行 C# 参数引用测试。
