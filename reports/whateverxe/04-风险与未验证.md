# 04 实机启动前风险与未验证事项

## 1. 风险清单

| ID | 风险 | 可能性 | 影响 | 依据 | 缓解 |
|---|---|---|---|---|---|
| R-01 | A7A0 + 内部 eDP 在 WEX 下黑屏/不亮 | 中 | 高 | 官方只实测 Raptor Lake-U；eDP on Raptor Lake-H/P/U 明确 “implemented but not tested” | 保留可启动的旧 EFI/U 盘；先不写内部 ESP；用独立 U 盘测试；失败时移除 WEX 或走 firmware framebuffer |
| R-02 | 3120×2080@90 Hz 不被支持，或只出 60 Hz/低分辨率 | 中高 | 中 | 官方已测内部面板最高 60 Hz，且不是这块 eDP | 首次启动先用默认分辨率；确认面板参数；不要承诺 90 Hz |
| R-03 | 安装器是 26.0–26.6，不是 26.7+ | 中 | 中 | 官方 Tahoe 要求 26.7+；构建器只选 Darwin 主版本 25 | 写盘前在 macOS 安装器/恢复环境确认 `sw_vers`；候选 EFI 的 WEX `MinKernel=25.7.0` 会阻止旧系统加载 WEX，但也就没有加速 |
| R-04 | WhateverXe Graphics 安装失败/被 Gatekeeper 拦截 | 中 | 高 | 官方 README：pkg 未签名/未公证；安装器不修改 EFI/SIP | 在 macOS 内允许安装；保留日志 `/var/log/install.log`；安装前确认 SIP 含 0x803；失败就用 Mac App 的 off/重试 |
| R-05 | SIP 实际为 `0x0A03`，而官方正常安装写 `0x803`；若安装器按“精确等于”检查会失败 | 低 | 高 | 官方 README 写 `0x803`；Mac App 用 `cur | 0x803` 保留其他位；未实机验证安装器检查方式 | 若安装器报 SIP 错误，把 `csr-active-config` 改为精确 `03080000` 后重启再装；这是待实机确认项 |
| R-06 | BIOS DVMT 不是 60 MB，当前 EFI 的 `-igfxdvmt` + 60 MB framebuffer 属性不匹配 | 中 | 中 | 官方 README：96 MB 时这两项不必要；60 MB 时才需要 | 在 BIOS 中设 DVMT Pre-Allocated = 96 MB（如可设）；若不可设，保留当前 60 MB 方案；不要同时改别的 framebuffer 参数 |
| R-07 | 亮度控制不工作 | 中 | 低 | `SSDT-PNLF` 已放入，但 A7A0/eDP 未实测；`BrightnessKeys` 只处理键盘快捷键 | 用 `SSDT-PNLF` + `BrightnessKeys` 先试；必要时改用其他 PNLF 方案 |
| R-08 | 睡眠/唤醒、外接显示器、DP/USB-C 重连异常 | 中高 | 中 | 上游 README 明确 sleep/wake experimental、DP reconnection known issues | 首次测试只做基本桌面；逐项测试；保留旧 EFI |
| R-09 | 使用旧 2.9.1 Mac App 搭配旧 2.9.1 EFI（SIP=0x03）时，Mac App 第二次运行直接装 Graphics 而失败 | 中 | 高 | `nullmoth-setup.sh` 旧逻辑；本次源码已修复但 2.9.1 发布包未重打包 | 用候选 EFI（SIP 已含 0x803），或先手工把 SIP 改为 0x803；或使用修复后的源码重新构建 Mac App |
| R-10 | WEX kext 加载了但 Graphics 没装，用户误以为已加速 | 高 | 中 | WEX kext 只在 EFI；加速 payload 在 `/Library`，需第二步 | 用 `kmutil showloaded | grep org.b00t0x.WhateverXe` 确认 kext；用 `system_profiler SPDisplaysDataType`/`ioreg` 确认加速；以 Mac App 的 Xe 状态为准 |
| R-11 | Windows 构建器生成的 EFI 在实机启动阶段失败（与 WEX 无关的 USB/ACPI/CPUID 问题） | 中 | 高 | 本项目未启动过这台机器；CPUID recipe 状态仍为 `theory` | 先按现有 2.9.1 风险清单验证基础启动；不要一次改多个变量 |
| R-12 | 把候选 EFI 写到内部 ESP，覆盖可启动的现有 EFI | 低 | 高 | 操作风险 | 只写独立 U 盘；保留旧 EFI 备份；本项目没有执行任何写盘 |

## 2. 实机启动前检查清单

1. **确认安装器版本**：macOS 26.7 或更新。若只有 26.0–26.6，先不要期待 WEX 加速。
2. **确认 BIOS DVMT**：能设就设 96 MB；不能设就保留当前 60 MB 方案（`-igfxdvmt` + framebuffer 属性）。
3. **准备独立 U 盘**：不要把候选 EFI 写入内部 ESP；不要覆盖现有可启动 EFI。
4. **保留回退路径**：保留 2.9.1 发布 EFI/可启动 U 盘；记录当前 BIOS 设置。
5. **准备网络**：WhateverXe Graphics 约 95 MB，Mac App 需要从作者 GitHub 下载；AX211 的 itlwm 在安装器内不可用，
   准备 Ethernet/USB 网卡或完整离线安装器。
6. **先验证基础启动**：不启用 WEX 的路径能进安装器/桌面，再打开 Xe；不要把 WEX 和 CPUID/ACPI 多个变量一起改。
7. **确认 kext 加载**：进入 macOS 后运行
   `kmutil showloaded --list-only | grep org.b00t0x.WhateverXe`。
8. **确认 SIP**：`nvram boot-args` 之外，用 IORegistry/OpenCore 配置确认 `csr-active-config` 含 `0x803`；
   `csrutil status` 在 OpenCore 下可能显示不直观。
9. **安装 Graphics**：用 1401 Mac App 的 Intel Xe 开关；第一次若要求重启，按提示重启，再运行第二次。
10. **验证加速**：`system_profiler SPDisplaysDataType`、Metal 设备列表、实际 UI 动画/视频；不要只看“WEX kext 已加载”。

## 3. 尚未实机验证的事项

以下全部是 **待实机验证**，不得写成已完成：

- 候选 EFI 能在本机 OpenCore 启动；
- macOS Tahoe 26.7+ 能安装、进入桌面；
- WhateverXe 0.8.0 kext 在 A7A0 上加载；
- Metal / OpenGL / OpenCL / H.264 / HEVC 加速；
- 内部 eDP 3120×2080 点亮、90 Hz、HiDPI；
- 亮度控制、键盘亮度键；
- WhateverXe Graphics v0.4.1 在本机安装成功、AuxKC 重建成功；
- SIP `0x0A03` 与安装器的兼容性；
- BIOS DVMT 实际值；
- 睡眠/唤醒；
- 外接显示器、HDMI/DP/USB-C、DP 重连；
- Wi-Fi（itlwm/HeliPort）、蓝牙、触摸板、触摸屏、音频；
- CPUID/拓扑 recipe（状态仍是 `theory`）；
- 任何“加速后功耗/温度/稳定性”结论。

## 4. 不能从本审计得到的结论

- 不能从“EFI 里有 WhateverXe.kext”推出“已经加速”；
- 不能从“A7A0 在官方设备表”推出“A7A0 已实机验证”；
- 不能从“ocvalidate 通过”推出“能启动”；
- 不能从“Mac App 有 Xe 开关”推出“Windows EFI Builder 已完成全部 WhateverXe 集成”；
- 不能从“上游 README 说 expected to work”推出“这台机器一定能工作”。

本审计的结论边界是：**代码路径、EFI 文件内容、上游文档、自动化测试**。实机结果必须由真实启动/安装产生。
