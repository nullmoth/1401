# 完整 macOS 安装器能力边界

严格区分四件事，**不能把下载成功说成可启动离线安装盘制作成功**：

1. 下载完整安装包；
2. 解包/校验安装资源；
3. 生成可启动安装介质；
4. 生成标准 Apple `createinstallmedia` 离线安装盘。

- 目录条目完整：标题、版本 26.7.3、构建 25G342、**18,388,869,343 bytes**、SHA-1 目录摘要、产品号。
- 真实 URL 可访问；前 1 MiB 正常返回；带 `Range: bytes=1048576-` 的续传请求返回 **HTTP 206**。
- **没有下载 18 GB 包**，所以“完整下载成功”未被声称。

## 2. 已验证：下载器的完整性逻辑（源码 + 测试）

`p1401/fullinstaller.py`：

- 目录大小是硬上限：读取封顶、服务器多发拒绝（修复 #161）。
- 超大 `.part` 删除重下；416/非瞬态 4xx 终止；瞬态退避；响应流必关。
- 目录有 `Digest` 时校验 SHA-1/SHA-256。
- `verify_xar()`：XAR 头、TOC 自身校验和、每个文件的 `archived-checksum`、文件偏移/长度不越界。
- 测试：`tests/test_fullinstaller.py` 21 项，含越界、416、403、流关闭、XAR 损坏、TOC 实体、放置读回。

**限制（明确）**：

- `verify_xar()` **不验证 Apple 的代码签名链**；它验证结构与归档校验和。Apple 的 `installer` 在 macOS 上打开包时才会验证签名。
- 没有 `archived-checksum` 的条目会被跳过；真实 Apple 包通常每个文件都有，但这不是签名认证。
- Windows 上无法调用 `pkgutil --check-signature`。

## 4. 未执行：生成可启动安装介质

1401 的 Windows 方案不是 `createinstallmedia`：

- 第一分区：FAT32，OpenCore EFI + `com.apple.recovery.boot`（Recovery 在线安装）。
- 第二分区（可选，≥32 GB U 盘）：exFAT，label `NMINSTALL`，放 `InstallAssistant.pkg` + `Install-macOS-from-this-disk.sh` + README。
- Recovery 里运行脚本：`installer -pkg ... -target <APFS 卷>`，把安装器装到目标盘，再 `startosinstall`。
- 代码：`p1401/fullinstaller.py`（`layout`、`diskpart_script`、`place`、`SCRIPT`）、`usbwriter.cli_write`（第二分区使用写盘最终磁盘号）。

**未执行**：真实 U 盘第二分区创建、18 GB 复制、Recovery 内运行脚本、`startosinstall`、安装完成。需要用户授权写盘 + 重启 + macOS 实机。

## 5. 未实现/不可能在 Windows 完成：标准 Apple `createinstallmedia` 盘

- Apple 官方 `createinstallmedia` 是 macOS 上的可执行文件，依赖 macOS 的 APFS/HFS+ 与安装器框架；Windows 原生无法生成标准 Apple 离线安装盘。
- 本项目**没有**声称能在 Windows 上生成 `createinstallmedia` 盘。
- 需要标准盘时：在一台 Mac 上运行 `createinstallmedia`，或使用 1401 的“第二分区 + Recovery 脚本”方案。
